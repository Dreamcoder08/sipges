# Sovereign desktop launchers (Windows and Linux)

Run SIPGES entirely on one person's laptop: their fork of the repo, data in embedded PGlite under
their user profile, no paid service required, opened as a desktop app from the Start menu or the
app launcher.

## Specs

- S1 — Owner: «ten en cuenta que la version sipges-desktop debe funcionar en la laptop de windows de mi prima» and «mi idea es hacerlo rapido posible ya que ella quiere soberania sobre todo que este en su laptop el proyecto , el repo , las cuentas donde tiene que pagar lso servicios y mas asi entiendes ??».
- S2 — Windows: `deploy/desktop/windows/install.ps1` (run once from the cloned repo with `powershell -ExecutionPolicy Bypass -File deploy\desktop\windows\install.ps1`) checks Node.js >= 24 and stops with the exact message «Node.js 24 o posterior es necesario: instálalo con `winget install OpenJS.NodeJS.LTS` y vuelve a ejecutar este script.» when missing; ensures pnpm 12.11.2 without relying on Corepack (absent from Node 25+): uses an existing `pnpm` of that major version, else `npm install -g pnpm@12.11.2`, stopping with the exact message «No se pudo instalar pnpm: ejecuta `npm install -g pnpm@12.11.2` en una terminal nueva y vuelve a ejecutar este script.» on failure; runs `pnpm install --frozen-lockfile` and `pnpm --filter @sipges/web build`; creates the state folder `%LOCALAPPDATA%\SIPGES` with `pglite\`, `uploads\`, a random 32-byte base64 `data-key` and a random `admin-password` (created once, never overwritten, readable only by the current user); creates Start-menu and Desktop shortcuts named «SIPGES» with `sipges.ico` that run `start.ps1` hidden; prints where the admin password is and how to back up the state folder.
- S3 — Windows: `deploy/desktop/windows/start.ps1` reuses a running server when `http://127.0.0.1:8000/health` answers (the address the server binds); otherwise starts `node apps/api/src/main.ts` hidden with `SIPGES_DATA_KEY`, `SIPGES_ADMIN_PASSWORD`, `SIPGES_COOKIE_SECURE=0`, `SIPGES_PGLITE_DIR`, `SIPGES_UPLOAD_DIR`, `SIPGES_WEB_DIR` and `SIPGES_HOST=127.0.0.1`, logging to `%LOCALAPPDATA%\SIPGES\api.log`; waits up to 90 s and on failure shows a message box pointing to the log; then opens Microsoft Edge (always installed) with `--app=http://localhost:8000`. MFA stays required (no `SIPGES_REQUIRE_MFA` override).
- S4 — Linux: `deploy/desktop/linux/sipges-desktop.sh` and `install.sh` do the same with `~/.local/share/sipges-local`, a `.desktop` entry and the hicolor icon, resolving the repo from the script's own location (no hard-coded paths), opening the first available of google-chrome-stable, chromium, microsoft-edge, brave, else `xdg-open`.
- S5 — Icon: `deploy/desktop/sipges.ico` (16, 24, 32, 48, 64, 128, 256 px) and `sipges.png` (512 px) generated from `design/app-icon/01-organic-terrain.svg` (provisional choice, replaceable by regenerating).
- S6 — Docs: `deploy/desktop/README.es.md` and `README.md` (English) in the cognitive-doc-design style: sovereignty model (fork in her own GitHub, clone, data in the state folder, no paid accounts needed; Cloudflare/Neon only to publish online; optional local AI with Ollama), install, daily use, update (`git pull` + rerun install), backup and restore of the state folder, and the honest limit that Windows was not tested on a real Windows machine by this change.
- S7 — Tests: `scripts/tooling.test.mjs` gains checks that the files exist, the PowerShell scripts contain the S2/S3 environment names and Node message verbatim, the Linux scripts pass `sh -n` and run their health/reuse path against a fake `curl` (no real server), and `install.sh` never overwrites an existing data-key or admin-password.
